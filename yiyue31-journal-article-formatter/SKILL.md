# 中文学术论文期刊格式化工具

将普通排版的中文论文 docx 转换为符合中文期刊投稿要求的正规格式文档。

> **路径约定**：本文档中 `{skill-dir}` 指本 skill 的安装目录（即 SKILL.md 所在目录）。所有脚本路径均基于 `{skill-dir}` 引用，例如 `{skill-dir}/scripts/analyze_docx.py`。

## 工作流程

### 第一步：收集信息

使用 AskUserQuestion 工具向用户确认以下内容（缺失时请用户补充或输入自定义意见）：

1. **原始论文 docx** — 待格式化的论文文件
2. **格式模板 docx**（可选）— 目标期刊的模板文件。如果没有，使用通用中文期刊规范
3. **英文摘要**（可选）— 提供 .md 或直接粘贴。如果没有，提醒用户补充
4. **作者信息** — 姓名、单位、城市、邮编（如未提供，询问用户）

### 第二步：分析原始文档

运行分析脚本提取原文档的结构和格式信息：

```bash
python {skill-dir}/scripts/analyze_docx.py 论文.docx
```

脚本会输出页面设置、每段文字的字体/字号/粗体/对齐方式、页眉页脚、表格和图片数量。

需要从输出中识别出：
- 论文标题
- 作者、单位（如有）
- 摘要、关键词
- 各级标题（前言、1 xxx、1.1 xxx 等）
- 正文段落（含引用标注 [n]）
- 参考文献列表

### 第三步：分析格式模板（如有）

对模板 docx 运行同样的分析脚本：

```bash
python {skill-dir}/scripts/analyze_docx.py 模板.docx
```

重点关注：

1. **页面设置**：边距、纸张大小
2. **分节信息**：哪些部分单栏、哪些双栏、栏间距
3. **字体字号标注**：模板中通常会在括号里标注格式要求（如"二号黑体"、"五号宋体"）
4. **页眉页脚**：内容和格式
5. **摘要区缩进**：左右是否缩进

详细的模板格式规范（页面、字体字号、页眉页脚、图表、参考文献格式等）已整理在 `{skill-dir}/references/template_spec.md` 中，供生成文档时查阅。

### 第四步：整理内容数据

将提取的内容整理为结构化数据，包括：

```
标题、作者、单位、摘要、关键词
正文段落列表 [{ type: "h1"/"h2"/"p", text: "..." }]
参考文献列表 [{ cn: "...", en: "..." }]
英文摘要、英文关键词
```

**参考文献双语处理**：中文期刊通常要求参考文献采用中英双语格式——先中文原文，再附英文翻译，末尾加 `(in Chinese)`。如果原文只有中文，需要翻译为英文。

### 第五步：用 docx-js 生成格式化文档

使用 Node.js 的 `docx` 包生成新的 docx 文件。

#### 环境准备

```bash
npm init -y 2>/dev/null
npm install docx
```

#### 代码模式参考

生成脚本所需的全部代码模式（字号常量、上标引用、双栏设置、页眉、首页段落、参考文献双语、完整文档结构）都在 `{skill-dir}/scripts/docx_patterns.md` 中。根据具体论文内容填充数据后生成 `generate_journal.js` 并执行。

常用字号对照：

| 名称 | 磅值 (pt) | docx-js 半磅值 |
|------|----------|---------------|
| 二号 | 22 | 44 |
| 三号 | 16 | 32 |
| 四号 | 14 | 28 |
| 五号 | 10.5 | 21 |
| 小五 | 9 | 18 |

#### 文档结构（通用中文期刊）

```
Section 1（首页，单栏）:
  - 中文标题（二号黑体加粗，居中）
  - 作者姓名（四号楷体，居中）
  - 作者单位（小五宋体，居中）
  - 中文摘要（五号黑体标签 + 楷体正文，左右缩进）
  - 中文关键词（五号黑体标签 + 楷体内容）
  - 中图分类号/文献标识码（五号黑体）
  - 英文标题（三号 Times New Roman 加粗，居中）
  - 英文作者（四号 TNR，居中）
  - 英文单位（小五 TNR，居中）
  - Abstract（五号 TNR 加粗标签 + 正文）
  - Key words（五号 TNR 加粗标签 + 内容）

Section 2（正文，双栏）:
  - 一级标题（四号黑体）
  - 二级标题（五号黑体加粗）
  - 正文（五号宋体 + TNR，首行缩进2字符）
  - 引用标注为上标

Section 3（参考文献，单栏）:
  - 参考文献标题（四号黑体）
  - 每条文献中英双语（小五号）

Section 4（文末引用格式）:
  - 引用格式行（斜体）
```

### 第六步：验证输出

```bash
python {skill-dir}/scripts/verify_output.py 输出文件_期刊格式.docx
```

脚本会检查：Section 栏数、首页段落完整性、上标引用、参考文献双语格式等，输出通过/失败/警告。

### 第七步：将分析文档保存到项目中

将分析过程写入 `文档分析与格式化方案.md`，使用 AskUserQuestion 工具请用户在执行前确认：确认执行或需要修改。

## 输出

- 格式化后的 docx 文件（文件名加 `_期刊格式` 后缀）
- 原始文件保持不变

## 注意事项

- 如果用户提供了模板，以模板格式为准，上面的通用规范仅供参考
- 参考文献的英文翻译要准确，保持和中文对应
- 作者信息由用户提供，不要随意编造（除非用户明确说"随便编"）
- 行距一般用单倍行距（`line: 276` 表示固定 13.8pt，或 `line: 240` / rule SINGLE）
- 生成脚本保存为 `generate_journal.js`，方便用户后续微调
