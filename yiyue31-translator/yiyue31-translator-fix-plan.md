## 1. 设计共识（已敲定，落地照此执行）

1. **判断 / 机械分流**
   - 判断类（注释）：两阶段——阶段A 翻译时**内联**插入 `«english»` 标记（包英文原文，如 `迁移«transfer»`），不直接加括注、不产出独立清单；阶段B 扫描残留 `«english»` 按标准裁定。
   - 机械类（代码 / URL / SVG / 模型名 / 缩写 / [KEEP] 术语）：翻译时内联原样保留，事后**脚本校验**，不走标记。
   - **keep-list**（定义）= 本篇须原样保留英文的元素集合 = [KEEP] 术语 + 专名/模型名 + 全大写缩写；由 Step 2 结构化输出，供 T3 校验脚本消费。
2. **注释保留标准**
   - **#1 词级**：读者无法从上下文推断该词含义 → 走 `«english»` 标记管线（主战场）。
   - **#2 / #3 句级**：金句/习语、**翻译无法传递的修辞效果**（双关/对仗/韵律，门槛要高，"写得好"不够）→ 走 Step 3 预先精选清单，格式 `**中文译文（English original）**`。
   - **#4 拆解**："语气冲击力/修辞力"并入 #3；"结论的重要性/确定性"**不触发注释**，改用中文加粗 / 短句 / 独占一行传达强调。
3. **优先级序列**：准确 > 流畅地道 > 必要注释；冲突时**流畅优先于注释**。
4. **校验哲学**：脚本管机械、审校管语义，互补不替代。
