# yiyue31-translator v2.1.0 迭代分析

**日期**: 2026-05-12
**基于**: v1.0.0 和 v2.0.0 的对比测试结果

---

## 一、测试结论

使用同一篇文章 (Notes from inside China's AI labs) 测试两个版本，v1.0.0 在翻译腔和金句展示方面明显优于 v2.0.0。

### 金句对比

| 指标 | v1.0.0 | v2.0.0 |
|------|--------|--------|
| 提取数量 | 13 条 | 3 条 |
| 附加信息 | 每条带"亮点说明"列 | 无 |
| 翻译质量 | "心中满是谦逊" — 意译自然 | "极大的谦卑" — 翻译腔 |

### 翻译腔对比

| 指标 | v1.0.0 | v2.0.0 |
|------|--------|--------|
| 检查机制 | 专项 Step 8.1，独立 subagent | 嵌入 FL 维度，scoring loop |
| 结果 | 4/5 分，问题定位到行号 | 7.0/10，两轮得分无改善 |
| 括号英文注释 | 较少（65+ 术语预定义） | 泛滥（20+ 处打断阅读） |

### 根因

v2.0.0 用自动化替代了多层质量门禁，但自动化不够有效：
1. 翻译腔检查从独立步骤降级为评分维度
2. Topic-based glossary (65+ 术语) 退化为 flat terms.md (15 术语)
3. 3 个对抗审查 + 1 个翻译腔检查 + 1 个综合校验 → 1 个 scoring loop
4. 金句提取从 13 条降到 3 条
5. Free 风格默认但规则模糊，缺乏 v1.0.0 的具体约束

## 二、合并策略

### 从 v1.0.0 保留

- 文章分析步骤 (topic/概念提取)
- 金句提取的 3 类分表 + "亮点说明"列
- 全部翻译规则（准确性优先、术语规范、修辞处理、格式保留、图文语言适配、尊重原文、译者注释、特殊词句规则、重意不重形、情感保真、表达流畅）
- 全部质量门禁：topic 对抗审查、特殊词句对抗审查、翻译腔专项检查、综合校验
- Markdown format checklist 引用

### 从 v2.0.0 保留

- 结构化英文格式（对 LLM 更清晰）
- Generate-Evaluate Loop 可复用模式
- 全自动流程（无用户交互）
- Flat terms.md + "Why" 列 + 自动维护
- Timer-based timeout
- YAML frontmatter
- 中英文间距规则
- 文件命名规范

## 三、决策记录

### 冲突 1：术语系统

**决策**：用 flat terms.md（v2.0.0 结构），不管理术语数量，交给 Step 9 自动维护自然增长。

### 冲突 2：默认翻译风格

**决策**：Free 为默认。保留 v1.0.0 的全部翻译规则。

### 冲突 3：质量门禁层级

**决策**：保留 v1.0.0 全部质量门禁（topic 对抗审查、特殊词句对抗审查、翻译腔检查、综合校验）。

### 冲突 4：用户交互

**决策**：全自动，无用户交互。

### 审查机制

**决策**：不使用"GAN"术语。实质要求：
- 启用独立 subagent 执行审查
- 提示词明确："以挑剔、专业、客观的眼光审查，只报告问题，不做表扬"
- PASS/FAIL 判定，不通过则修正后重跑该步骤
