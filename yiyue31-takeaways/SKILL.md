# Article Rewriting and Takeaways Generation Skill

此技能用于将文章总结成自己的心得体会，生成结构清晰、可发表的markdown文档。包含了用户和AI互动的环节，用来总结心得。

## workflow

严格按照以下步骤执行：

### Step 1: 格式化输入文档

首先将用户输入的内容转换为统一的Markdown文档。

**输入来源处理：**

1. **URL输入**：优先使用本地已安装的skills（如下载文章、转换文章、抓取网页、操作网页、查看网页等），其次使用 `wget` 或 `curl` 打开网页并下载文章内容。
2. **文件路径**：如果用户提供的是文件路径（.md, .txt, .pdf, .docx等），读取文件内容
3. **粘贴内容**：如果用户直接粘贴了文本内容，直接使用

**保存原始文档：**

创建目录结构并保存原始内容：
```
{title}/raw-{title}.md
```

title从原文中提取，或使用简短的描述性名称。

### Step 2: 分析原文

阅读并分析原文，提取以下信息：

- 文章的核心主题和主旨
- 文章结构（章节划分）
- 按章节分析关键观点和论据
- 文章类型（技术文章、管理心得、经验分享、学术论文等）
- 原文的篇幅和复杂度
- **提取实体名词**：识别关键名词、概念、人物、组件、技术术语等，分析它们之间的关系
- **术语分析**：提取关键术语和概念，参考 `rules/rewrite-guidelines.md` 判断是否可改写
- **金句提取**：筛选出彩表达、亮眼、有记忆点的句子，作为总结中的亮点
- **不可改写内容识别**：识别数据、人名、公司名、产品名等不可改写的内容，参考 `rules/rewrite-guidelines.md`

**保存分析结果：**

```markdown
# 分析结果

## 核心主题
[文章的核心主题和主旨]

## 文章结构
[章节划分]

## 实体名词
[关键名词、概念、人物、组件、技术术语等]

## 术语分析
| 原文位置 | 原文术语 | 中文术语 | 改写建议 |
|---------|---------|---------|---------|
| 章节/段落 | term | 术语解释 | 保留/改写 |

## 金句提取
| 原文位置 | 原文 | 亮点说明 |
|---------|------|---------|
| 章节/段落 | 金句内容 | 为什么出彩 |

## 不可改写内容
| 原文位置 | 内容类型 | 原文内容 | 处理方式 |
|---------|---------|---------|---------|
| 章节/段落 | 数据/人名/公司名 | 具体内容 | 完全保留 |
```

```
{title}/analysis-raw-{title}.md
```

**分析结果检查（启用subagent）**：
启用subagent对分析结果进行清单检查，验证：
- 核心主题是否准确
- 文章结构是否完整
- 实体名词是否遗漏
- 术语提取是否准确
- 金句提取是否恰当
- 不可改写内容识别是否正确

如发现问题，subagent提出修改建议，进行调整后继续。

### Step 3: 生成实体关系图（可选）

根据Step 2提取的实体，生成Mermaid代码。数据缺失或者关系不确定时，请用户协助。

**AI判断是否需要生成：**
- 文章复杂度高（如技术架构、系统设计、多组件交互）→ 建议生成
- 文章简单直接（如个人心得、经验分享）→ 可跳过

**询问用户：**
AI告知用户判断结果，询问是否需要生成实体关系图。

**支持的可视化类型：**

- **思维导图（mindmap）**：展示概念的层级关系
- **实体关系图（ER）**：展示实体之间的关联
- **流程图**：展示流程或步骤

**输出格式：**

```markdown
# [title] - 实体关系图

## 核心实体
[列出文章中的关键名词、概念、人物、组件等]

## 思维导图
\`\`\`mermaid
mindmap
  root((主题))
    子主题1
      概念A
      概念B
    子主题2
      概念C
\`\`\`

## 实体关系图
\`\`\`mermaid
erDiagram
    实体A ||--o{ 实体B : 关系
\`\`\`
```

**保存位置：**

```
{title}/entities-{title}.md
```

**用户确认**：向用户展示实体关系图，确认提取的实体是否准确、关系是否完整。等待用户确认后再继续。

### Step 4: 交互式讨论与记录

本步骤采用**交互式讨论**模式，AI和用户通过对话深入探讨文章内容，类似于导师与学生、同事之间的讨论。

**讨论规则：**

1. **AI问AI（自问自答）**：针对文章中的难点，AI生成问题并记录答案
   - "文章中提到的[概念X]具体是指什么？"
   - "[技术Y]与[技术Z]有什么区别？"
   - "作者为什么选择[方案A]而不是[方案B]？"

2. **AI与用户交互讨论**：
   - AI可以发起提问，用户回答后，用户可以追问，AI继续回应
   - 用户可以主动提问，AI回答后可以追问用户的理解
   - 往复对话，深入探讨
   - 用户决定何时结束讨论

**讨论主题建议：**

- 对概念的理解和澄清
- 与用户经验的联系
- 观点的启发和思考
- 实际应用的探讨

**保存讨论记录：**

```
{title}/qa-{title}.md
```

格式示例：
```markdown
# 交互式讨论记录

## AI问AI（自问自答，帮助理解）
1. Q: [问题] 
   A: [AI根据文章内容的回答]

2. Q: [问题]
   A: [AI根据文章内容的回答]

## AI与用户讨论

### 讨论主题1：[主题]
**AI**: [问题或观点]
**用户**: [回答或疑问]
**AI**: [回应或追问]
**用户**: [进一步思考]

### 讨论主题2：[主题]
**用户**: [主动提问]
**AI**: [回答]
**AI**: [追问用户的理解]
**用户**: [回应]
```

**智能默认值：**

AI根据文章内容自动判断改写参数，提供默认推荐：
- **改写目的**：AI根据文章类型自动推荐（如学习笔记/分享文档/博客文章）
- **目标读者**：AI根据文章领域判断（如技术人员/管理者/普通读者）
- **重点侧重**：AI根据文章结构判断（如技术细节/实践经验/理论理解）
- **表达风格**：AI推荐合适的风格（见Step 5）

用户如果想修改默认值，可以在讨论中或之后主动告知。不主动修改则使用AI推荐。

### Step 5: 选择内容结构模板和表达风格

**输入类型判断：**
在Step 4交互式讨论的同时或之前，根据 `templates/input-types.md` 判断输入类型：
- **内容领域**：TECH（技术）、MGMT（管理）、ACAD（学术）、POPU（科普）、PROD（产品）、BIZN（商业）
- **文章结构**：TUTOR（教程）、CASE（案例）、THEORY（理论）、EXP（经验）、REVIEW（综述）、GUIDE（指南）、INTERVIEW（访谈）

例如：`TECH-CASE`（技术案例分析）、`MGMT-EXP`（管理经验分享）

告知用户判断结果并确认。

**读取模板文件：**
- `templates/content-structures/` - 10种内容结构模板
- `templates/output-styles.md` - 6种表达风格定义
- `rules/forbidden-words.md` - 禁止词汇表

**AI推荐内容结构模板：**
根据文章内容，推荐最适合的内容结构模板。

示例：
- 技术案例分析 → 推荐 `04-case-analysis.md`（案例解析型）
- 项目复盘总结 → 推荐 `02-review.md`（复盘总结型）
- 零基础入门教程 → 推荐 `01-tutorial.md`（教程入门型）

**用户确认或指定内容结构模板：**
用户可以接受AI推荐，或指定自己的选择。

**选择表达风格：**
AI根据文章内容推荐合适的表达风格，用户确认或指定。

详细风格定义见 `templates/output-styles.md`。

**记录选择：**
更新 `templates/history.md`，记录本次选择。

**选择合理性检查（启用subagent）**：
启用subagent对模板和风格选择进行常规审查，验证：
- 内容结构模板与文章类型匹配度
- 表达风格与目标读者匹配度
- 模板+风格组合的合理性

如发现问题，subagent提出调整建议。用户确认后继续。

### Step 6: 生成心得草稿

根据选择的内容结构模板，生成心得草稿。

**读取对应模板文件：**
读取 `templates/content-structures/[模板名称].md`，获取章节结构。

**按照模板生成草稿：**
严格按照模板的章节结构生成内容。

**从分析结果中提取亮点：**
从Step 2分析结果中提取以下内容：
- **金句**：筛选出彩表达、有记忆点的句子
- **关键术语**：选择核心概念，避免过多

选取能提升阅读体验和文章质量的部分，在正文中突出显示。

**显示格式：**
在单独的一个段落中用引用格式展示：
```markdown
> 中文翻译(英文原文)
```

**选取原则：**
- 优先选择有感染力、有记忆点的金句
- 术语选择核心概念，避免过多
- 保持文章流畅性，不要过度打断正文

**保存位置：**
```
{title}/takeaways-{title}.md
```

**用户确认：**
向用户展示草稿，等待用户确认或修改。只有用户确认后，才继续生成最终文章。

### Step 7: 生成最终文章

基于确认后的心得草稿和选择的表达风格，生成最终改写文章。

**生成原则：**
1. **保持核心信息准确**：不歪曲原文的核心观点和事实
2. **融入个人理解**：将原文内容转化为自己的语言和理解
3. **结构清晰**：使用明确的章节划分，便于阅读
4. **可发表标准**：语言流畅、逻辑清晰、格式规范
5. **符合表达风格**：严格按照选择的表达风格生成
6. **避免禁止词汇**：检查并避免使用rules/forbidden-words.md中的词汇

**表达风格检查：**
- FIRST：尽量避免使用"我"
- THIRD：禁止使用"指出"、"文章指出"等AI味儿浓的表达
- TEACH：避免死板的连接词（"首先"、"然后"、"接下来"、"最后"）
- PRACTICE：使用行动导向的语言

**保存位置：**
```
{title}/final-{title}.md
```

**校验环节（启用subagent）**：
生成完成后，启用subagent进行对抗审查，检查：
1. 是否包含禁止词汇（rules/forbidden-words.md）
2. 是否符合内容改写指南（rules/rewrite-guidelines.md）
3. 是否符合选择的表达风格
4. 文章概述是否连贯自然
5. 是否有逻辑问题或表达不清之处

subagent提出修改建议，如无问题则确认完成。

### Step 8: 总结和确认

完成改写后，向用户总结：
- 原文保存位置
- 分析结果保存位置
- 实体关系图保存位置
- 提问记录保存位置
- 心得草稿保存位置
- 最终改写文章保存位置
- 改写的主要变化和调整
- 询问是否需要进一步调整
