# yiyue31-notes 开发计划

## 项目概述

**目标**：开发一个独立的 skill，用于合并 `yiyue31-summary` 和 `yiyue31-talk` 的输出，生成完整的学习笔记文档。

**核心定位**：合并工具（不是编排者）

**输出类型**：
- 博客版：精简、对外友好、适合发布
- 个人版：详细、保留讨论过程、适合回顾

## Phase 2: 模板设计（当前阶段）

### 2.1 模板组织方式

**最终确定的两种方案**：

#### 方案A：简化版（线性分层结构）

**适用场景**：快速实现，MVP

**结构**：
```markdown
## 1. 快速了解层

### 文章概述
[summary的概述部分：要点速览]

### 我的观点概览
[talk的观点概览：核心关注、我的理解、我的异议/补充]

## 2. 详细内容层（线性展示）

### 文章核心内容
[summary的要点部分 + 章节部分：按章节总结]

### 我的观点详情
[talk的观点详情：按话题展示，包含原文位置]

## 3. 总结层

### 文章核心价值
[summary的洞察和启发]

### 我的收获与启发
[talk的收获与启发]

### 实践建议
[合并两者]

## 4. 附录（可选）

### 讨论记录
[talk/qa：完整讨论过程]

### 关键术语表
[talk/analysis-raw：术语表]
```

**优点**：
- 实现简单，不需要章节匹配
- 逻辑清晰：全局 → 局部 → 总结
- 快速可用

**缺点**：
- 详细内容层仍然是线性分离
- 读者需要自己建立观点和章节的对应关系

---

#### 方案B：优化版（分层交织结构）

**适用场景**：深度整合，最佳阅读体验

**结构**：
```markdown
## 1. 快速了解层

### 文章概述
[summary的概述部分：要点速览]

#### 文章内容
[summary：章节1的内容总结]

#### 我的看法
[talk：对应章节1的用户观点]
（如果无法精确匹配，展示相关观点）

### 章节2：[章节标题]
#### 文章内容
[summary：章节2的内容总结]

#### 我的看法
[talk：对应章节2的用户观点]

### 其他观点
[无法匹配到具体章节的观点，单独列出]

## 3. 总结层

### 文章核心价值
[summary的洞察和启发]

### 我的收获与启发
[talk的收获与启发]

### 实践建议
[合并两者]

### 适用边界
[talk的适用边界]

## 4. 附录（可选）

### 观点映射表
[talk/viewpoint-mapping：完整的观点映射关系]

### 讨论记录
[talk/qa：完整讨论过程]

### 关键术语表
[talk/analysis-raw：术语表]
```

**优点**：
- 内容紧密关联，阅读体验流畅
- 观点和文章内容自然对应
- 符合"边读边思考"的阅读习惯

**缺点**：
- 实现复杂，需要章节匹配逻辑
- 依赖 viewpoint-mapping 的准确性
- 维护成本较高

### B.1 输入文件依赖

**必需文件**：
- `{title}/summary/final-summary-{title}.md`
- `{title}/talk/user-viewpoints-{title}.md`
- `{title}/talk/viewpoint-mapping-{title}.md` ⚠️ 必需

**可选文件**：
- `{title}/talk/qa-{title}.md`
- `{title}/talk/analysis-raw-{title}.md`

### B.2 章节匹配逻辑

#### B.2.1 匹配规则

从 viewpoint-mapping-{title}.md 读取映射表：

```markdown
| 观点ID | 用户观点 | 目标章节 | 放置方式 | 优先级 |
```

**匹配策略**：

1. **精确匹配**：
   - 如果观点有明确的"目标章节"，直接放到该章节后

2. **关键词匹配**：
   - 如果没有明确章节，根据"原文位置"的关键词匹配 summary 的章节标题

3. **无法匹配**：
   - 放入"其他观点"部分

#### B.2.2 内容组织顺序

```
对于 summary 中的每个章节：
  1. 输出章节内容
  2. 从 viewpoint-mapping 查找对应该章节的观点
  3. 如果找到，输出"我的看法"
  4. 如果没有，跳过

处理完所有章节后：
  1. 收集无法匹配的观点
  2. 输出到"其他观点"部分
```

### 3.4 错误处理策略

#### 文件不存在错误
```
IF {title}/summary/ 不存在:
    提示："未找到文章总结。请先运行 /yiyue31-summary 生成文章总结。"
    停止执行

IF {title}/talk/ 不存在:
    提示："未找到用户观点。请先运行 /yiyue31-talk 生成用户观点。"
    停止执行

IF viewpoint-mapping 不存在（仅方案B）:
    提示："方案B需要观点映射文件。请选择方案A，或确保 /yiyue31-talk 生成了 viewpoint-mapping 文件。"
    建议降级到方案A
```

#### 内容解析错误
```
IF 无法解析 final-summary:
    提示："文章总结格式不正确。请确保使用最新版本的 /yiyue31-summary。"

IF 无法解析 user-viewpoints:
    提示："用户观点格式不正确。请确保使用最新版本的 /yiyue31-talk。"

IF viewpoint-mapping 格式不正确:
    提示："观点映射文件格式不正确。降级使用方案A。"
    自动切换到方案A
```

#### 匹配失败处理（方案B）
```
匹配失败率 < 20%:
    警告："部分观点无法匹配到具体章节，已放入'其他观点'部分。"

匹配失败率 >= 20%:
    警告："大部分观点无法匹配章节。建议使用方案A或检查 viewpoint-mapping 文件。"
    询问是否继续

匹配失败率 >= 50%:
    错误："观点映射严重不匹配。请检查 viewpoint-mapping 文件，或使用方案A。"
    停止执行
```

#### 方式1：线性模式（Linear）
- 结构：Summary 完整展示 → Talk 完整展示
- 适合：快速阅读，先了解文章再了解观点
- 流程：
  ```
  [文章概述] → [核心内容] → [我的观点] → [总结]
  ```

#### 方式2：交织模式（Interleaved）
- 结构：按章节 Summary → Talk 对应观点穿插
- 适合：深度阅读，边看文章边思考
- 流程：
  ```
  [章节1 Summary] → [我对章节1的看法]
  → [章节2 Summary] → [我对章节2的看法]
  → ...
  → [综合总结]
  ```
