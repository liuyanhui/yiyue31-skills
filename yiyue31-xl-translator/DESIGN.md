## 0. 设计基线（已裁决，概括）

1. **完全独立 skill**，fork 资产一次性拷贝（含翻译方法论资产：glossary 管线、«» 管线、consistency-checklist.js——评审 X6 教训）
2. **零介入**：披露不询问；准确性维度永不自动跳过（⚖️ 确认过的 carve-out）
3. **质量优先**（2026-08-30 裁决）：四维度审校独立、全覆盖、不抽样，且**审校单元减半**（每 chunk 切两半分两次送审，防大块注意力稀释——调用量 ~52→~84 已知情批准，不含探针；含探针 4 见 §4 ~88）；预算只做透明对账**不设硬顶**；返工超 3 轮**升级**（换模型重翻）而非降级；耗时/token 让位于质量——跑得完靠粒度 + 断点续跑，绝不靠砍质检
4. **关卡结构性**：终检重执行一切确定性检查；交付名与终检 PASS 绑定（临时名不命中 `classify()`）；新鲜度按"产物集合+豁免清单+固定顺序"实现；hook 编排关卡推迟二期
5. **术语种子**：一次性拷贝 translator 的 terms.md 作种子；周期合并**推迟为人工习惯**（非机制——2026-08-30 一致性终检裁决，关闭 REQ 开放问题 1）
6. **评审四裁决**（2026-08-30 拍板）：①待决清单终态 = 自动转 PENDING-USER 挂起（质量优先下不带病交付）；②N>1 并发实现推迟 v2（参数位保留）；③审校单元减半采纳；④文风基准卡采纳（Step 2 新增固定产物）

## 1. 设计原理（图解：为什么不溢出、为什么有质量）

> 核心口诀：**上下文里永远只装"一个单元"，磁盘上装着全部。** 上下文溢出的本质是"把历史都背在身上"——本设计没有任何角色背历史：主 agent 只看磁盘状态，subagent 用完即弃，文件系统是唯一记忆。

### 1.1 分层记忆架构

```
┌─────────────────────────────────────────────────────┐
│          上下文窗口（易失，会话结束就没了）              │
│   主 agent（编排者）                                  │
│   只装：SKILL.md 流程 + 状态命令输出 + 当前单元路径      │
│         │ 派发一个单元                                │
│         ▼                                            │
│   subagent（干活的，用完即弃）                          │
│   只装：1 个 chunk（8-15KB）+ 上下文包（≈5KB）          │
│   → 交出译文或报告 → 整个上下文销毁    ← 每次新建        │
│   ★ 任何时刻，活上下文 ≈ 一个单元的量（~25KB），        │
│     与总工作量完全无关                                  │
└───────────────────────┬─────────────────────────────┘
                        │ 读写
                        ▼
┌─────────────────────────────────────────────────────┐
│        文件系统（唯一记忆，持久，随便多大）              │
│   xl-translator/<title>/（原文/chunks/译文/报告/状态）  │
└─────────────────────────────────────────────────────┘
```

类比：项目经理桌上永远只放一章的材料，档案馆（磁盘）放着全书；每个译员领一章进小房间，干完走人。

**上下文预算表**：

| 角色 | 装载内容 | 量级 | 生命周期 |
|---|---|---|---|
| 主 agent | SKILL.md 流程 + 状态输出 + 当前单元路径 | ~30KB | 一个会话 |
| 翻译 subagent | 1 chunk + 上下文包（glossary/keep-list/special-phrases/brief/交接包） | ~25KB | 一次调用 |
| 审校 subagent | 半块原文 + 半块译文 + 只读语境段 + checklist（+glossary 投影/brief/文风卡全文+anchor 节选——R7/R10） | ~20KB | 一次调用 |
| 冷读者 | 全稿或接力段（>30KB 分段） | ≤30KB/段 | 一次调用 |

### 1.2 规模特性：每步 O(1)，总量 O(N)

```
  64KB 文档：  8 chunk / 16 半块 ≈ 88 次调用（含探针 4）   每次装 ~25KB
  500KB 文档： 45 chunk / 90 半块 ≈ 450+ 次调用             每次装 ~25KB   ← 恒定不变！
  涨的只有：日历时间、会话数、磁盘文件数（线性）
  不涨的：任何一次调用/任何一个会话的上下文占用
```

并发注记：`--concurrency N`（默认 1）允许 N 个 worker 同时活——上下文仍 O(1)/单元，但**内存 O(N)**；交接包预生成消除了跨 chunk 先后依赖，故可并发（详见 §2 横切）。

### 1.3 长跑不断线：会话接力

```
小时  0        1         2         3        …   12
      ┌─会话1───┐┌─会话2───┐┌─会话3───┐
      │翻译1-3  ││翻译4-6  ││四维审校… │
      └─干净退出─┘└─干净退出┘└────────…
          │检查点（每单元完成即落盘，不是每会话）
          ▼
   /compact、上下文压缩、OOM、关机、限流、/clear
          │  全部走同一条恢复路径
          ▼
   新会话 → 跑一条状态命令 → "chunk 5，阶段：审校-翻译腔" → 照单继续
```

主 agent 不依赖会话记忆——换会话、被压缩、被断电对它没有区别（工厂换班，交接靠档案不靠脑子）。

### 1.4 质量流水线速览（详细步骤见 §2）

```
原文
 │ 分段(8-15KB) ──关卡：拼接 sha === 原文 sha
 ▼
译前：glossary(一条一译) ──译前评审 subagent──→ 不过打回
 ▼
每 chunk：翻译A → 裁定B → 机械校验(脚本硬门) → 审校×4(独立/异模型)
   ▲                                        │ 报告(头部记 sha)
   └────────────────────────────────────────┘
      修复闭环：改译文→报告 stale→重审；超 3 轮→换模型重翻
 ▼
统稿(全稿一致) → 冷读者(全稿通读) → 终检(重执行一切+能力核验)
                                    │ PASS 才原子改名交付
```

**三条柱子**：

| 柱子 | 机制 | 防的是什么 |
|---|---|---|
| 独立复眼 | 翻译者 ≠ 审校者 ≠ 统稿者 ≠ 冷读者，独立 subagent、尽量异模型 | 自己查不出自己的盲区 |
| 结构关卡 | 每个"完成"由脚本从文件系统**重演验证**，不信任任何自述 | 假报告、假验收（上次事故病灶） |
| 版本绑定 | 报告头部记被审译文 sha——译文一改，报告自动作废重审 | "修过但没复审"的蒙混 |

### 1.5 对偶关系：防溢出与防造假是同一套设计

| 维度 | 溢出问题 | 质量问题 |
|---|---|---|
| 对策 | 状态外置到磁盘（上下文 O(1)） | 关卡内置到脚本（验证不依赖自觉） |
| 共同点 | **都不信任 agent 的自觉与记忆**——一个把记忆外包给文件系统，一个把验证外包给确定性脚本 | |

上次事故证明：靠 agent 自觉既会造假也会漂移。本架构把"记"和"验"都从 agent 身上拿走。

## 2. 技能步骤分解（SKILL.md 主流程）

> 执行者标记：`[脚本]` 确定性、零信任要求；`[subagent]` 独立调用（串行，计预算）；`[主]` 主 agent 编排与本地轻活。每步末尾的关卡决定能否进入下一步。

### Step 0 发起与预检 `[主+脚本]`
- 输入：原文（URL/路径/粘贴）。可选 translation-brief，缺省默认值（技术读者/意译/中等注释密度/发布用途）——**不问用户**。
- 动作：取文→markdown 化→**规模与结构预检**（大小 + 标题密度估算 chunk 数；>40KB 才走 xl，否则**自动交接给 translator 执行**而非让用户重发——2026-08-30 评审裁决；"≥8 chunk"预估条件废除，属旧粒度遗留）。测试/标定旁路：`--xl-force` 强制走 xl 全流程（M3 的 20KB 试跑用，干跑 C-3 裁决）。
- 预检附**原文完整性 WARN**：末句截断/围栏不配对等异常提示不阻塞（干跑 C-10）。
- 工作目录：**`xl-translator/<title>/`**（2026-08-30 Yiyue 裁决：与 `translator/`、`summary/` 等其他 skill 的输出目录**完全分开**；符合 refined-stock 短名规则；中间产物用临时名，终检 PASS 才改名为正式交付文件）。**EOL 归一责任单点化（G8，2026-08-31）**：`original-<title>.md` **落盘即统一归一为 LF**（CRLF→LF），下游一切 sha 一律按落盘文件字节原样计算——否则 Windows 源文档会让终检拼接 sha 恒不匹配、假错死锁。
- **预算公告**（通知非询问）：输出预估 chunk 数、subagent 调用基线、预计会话数，**加一行 brief 披露**（如"当前按技术读者/意译/中等注释密度/发布用途处理，想改就说'换成直译/注释少点'"——R6）。**R16（2026-08-31 采纳）**：公告末附**喊停方式**（一句话说明如何中断）；支持**"先翻第 N 章出样张"**——用户确认风格后放全量，与 R5 章↔chunk 映射披露共享机制（动词入 M1b 动词表）。**原文分母外锚（G1，2026-08-31）**：公告含脚本计算的原文 sha1（前 12 位）+ chunk 数——聊天留痕即工作区外锚点，交付时供用户对照（Step 10 回显同一 sha；防"改写原文+重算 manifest"的自洽篡改 silently 通过全部关卡）。
- 关卡：无（本步不改翻译产物）。

### Step 1 分段 `[脚本]`
- fork doc_segmenter 改造：目标 8-15KB、跨级别合并、code block/表格原子不可切。**巨块条件收紧（R11-B 裁决 2026-08-31）**：仅 fence/表格**原子块**可超限单 chunk 并以 X 标记；散文巨块强制再切（段落边界切，落回目标带）——翻译单元与审校半块同落甜点区。
- 产物：`chunks/` + `manifest.md`（heading 树）+ `progress.json`（**缓存非事实源**，明文注明）。
- 关卡：**拼接 sha === 原文 sha**（钉死分母，防偷删）；chunk 尺寸分布落目标带，否则自动调参重分段（附录 A #1 闭环）。

### Step 2 译前分析 `[主+subagent×1]`（分析本地生成；>64KB 分段提取）
- 产物：`analysis-`（受众/概念/链接）、`glossary-`（**一条一译**，脚本扫双选条目→自动打回重裁定直至零双选）、`keep-list-`、`special-phrases-`、brief 落盘，另产出**全文标题树预译**（含目录；正文与目录标题照抄既定译名，治目录↔正文标题不一致——R19）。**既定译法投影由脚本按各 chunk 原文扫描生成**（大小写/单复数归一，取该 chunk 将出现的条目子集——R8-b，2026-08-31 采纳）。
- 评审：**译前产物评审 subagent ×1**（独立）：复核 glossary 一条一译合规/覆盖度、keep-list 完备性、special-phrases 提取质量——不过即打回重做（质量优先，2026-08-30 裁决）。**打回 ≤2 轮（G6，2026-08-31）**：超限升级评审模型一次，仍不过转 PENDING-USER——评审循环与 Step 5/7 同享终止条件，不留无界空转口。
- **文风基准卡**（2026-08-30 采纳）：把原文文风特征定为中文写作规则（句式节奏/语体/称谓/标点习惯/比喻处理策略等），经译前评审复核；喂给全部译者，并作为统稿与冷读者的判卷标准——治"每章都对、拼起来是八个人译的书"。卡内含**文体变化轴**（分章文体变化的记述）；文体分化明显的书按部设多个范文锚点（R19）。
- 大文档保护（>64KB）：分析改 **subagent 分段提取 + 脚本合并去重**，主 agent 不整读原文（守住 O(1)）。
- 关卡：glossary 零双选（**双选打回 ≤3 轮，超限转 PENDING-USER——G6，2026-08-31**，歧义术语反复横跳不再无界燃烧）；keep-list 非空（若原文有机械元素）。
- terms.md 种子拷贝在此步执行（首次）。

### Step 3 翻译（阶段A） `[subagent]` ×N 串行
- 输入（**边界交接包**，开工前统一预生成，**五件套规格**——2026-08-30 评审冻结）：
  ① 全文 chunk 地图（每 chunk 1-2 行"确立了什么"，远距离回指的锚；**含全文标题树既定译名**——R19）；
  ② 前 chunk 末段摘要（含"留下了什么"：未决问题/预告/待展开概念）；
  ③ 既定译法投影（glossary 中该 chunk 将出现的条目子集 + 反复用语 + **该 chunk 涉及的标题条目**，**per-chunk 投影保 O(1)**）；
  ④ 贯穿性比喻/案例/叙事线台账（确立后全文沿用）；
  ⑤ 文风基准卡。
- **串行增强**（默认并发 1 时零成本）：派发时由脚本**追加邻 chunk 已通过译文的真实中文末段 300-500 字**（sha 绑定，源 chunk 变更即检测失效）——译者见到目标语实际面貌；N>1（v2）时退回纯预生成。
- **范文锚点**：chunk 1 通过审校后，节选 300-500 字定稿例文入后续交接包（比规则更直观的文风锚）。
- 其余输入：chunk 原文 + keep-list + special-phrases + brief。输出：带 `«english»` 标记的译文（硬禁止直接括注；金句/习语按精选表）+ **"glossary 外自裁定术语"回传清单**（R8-a，2026-08-31 采纳）：阶段A 发现表外新术语时带回，主 agent 一条一译裁定入表并更新下游 chunk 投影。
- **主循环执行序（干跑 C-2 裁决，2026-08-30）：逐 chunk 流水**——每个 chunk 走完 翻译→裁定→机械校验→四维审校→修复（过审）后，才派发下一个 chunk 的翻译。phase 视图（各 Step 的 ×N 标记）仅用于预算汇报与文档叙述，不是执行序。理由：范文锚点（chunk-01 过审后生成）与串行增强（邻 chunk 已审中文末段）都依赖"前 chunk 已过审"；逐 chunk 流水同时是会话预算的天然切割点。
- 关卡：无（信任后置到 Step 5/6）。

### Step 4 注释裁定（阶段B） `[subagent]` ×N 串行（⚖️ v1 不合并 A/B，标定后可复议）
- 输入：阶段A 译文 + chunk 原文（裁定需要语境：是否术语首现/金句）+ special-phrases 精选表 + 注释密度档（brief）+ **全文已裁定保留注释术语集**（此前 chunk 裁定台账的聚合视图——"术语首现"是全文概念，同一术语括注全文唯一，防各 chunk 重复保留致密度膨胀——R9）。
- 裁定每个 `«»`：保留→`中文（English）`，删除→去标；扫直接括注违规。
- **裁定台账**：每个 «» 的裁定记录逐条落盘——终检据台账验证"最终文本括注 **=== 台账'保留'集合**（双向相等——G3，2026-08-31：单向 ⊆ 对空台账空泛通过，全删 «» 即零工作量合规）"，使直注兜底扫描可判定（2026-08-30 评审补充）。
- 关卡：`«»` 残留 = 0（正则）。

### Step 5 机械校验关卡 `[脚本]` ×N
- fork verify-mechanical 扩展：原五项 + **数字/单位保真 + 散文残留英文阈值 + 中英间距 + 段落计数/长度比下限（防空洞化）**。
- **术语兑现硬判（R8-c，2026-08-31 采纳）**：该 chunk 投影条目的**既定译名或登记别名**未在译文出现即打回（别名放宽防变体写法误伤）；输入约定（投影路径）已在 verify-mech.mjs 预留，**实现随 M1b 投影文件格式冻结后落地**——先定接口再编码。
- **修复后强制重跑**；不过自动打回重翻（计返工轮次）。**同 chunk 机械打回 ≤2 次** → 并入 Step 7 升级出口（换模型重翻）→ 仍不过转 PENDING-USER——机械路径与审校路径共用终止条件，无无限重翻（R4）。
- **brief 阈值安全域 clamp（G2，2026-08-31）**：brief 是阈值来源但属被防对象可写范围——阈值只能**收紧**不能放宽：各键 clamp 到安全域（残留英文 run 上限、长度比下限等有界；**中英间距不可经 brief 放宽**），越界键值按安全域边界生效；非默认阈值全部进 REPORT 首屏披露。防"brief 塞 `max-en-run:999` 灭掉三道硬判、终检同参重跑照 PASS"。
- **手修路径机械后果（G7，2026-08-31）**：PENDING-USER 菜单②（用户手修译文）路径下，间距类违规由脚本**自动补空格（diff 披露）后重跑**，不自动重翻；仅结构性 FAIL（数字缺失/代码改动/漏译）才提示用户。手修 chunk **永不自动重翻**——手修是解挂出口，不是新的打回源（否则"100万"式人写无空格必触发重翻覆盖手修，构成销毁回路）。
- 结果落盘 `verify-results.json`（含译文 sha；终检不信任它，会重跑）。

### Step 6 审校 `[subagent]` 串行——四维度独立全覆盖 + 单元减半（质量优先）
- **审校单元 = chunk 半块**（2026-08-30 采纳）：每 chunk 切两半分两次送审——原 prompt 实战于 1.2KB 粒度，15KB 一次送审注意力必然稀释（名义全覆盖、实际隐性抽检）；半块送审覆盖不减、看得更细。送审半块附**另一边界段落（或 chunk 首 1-2 段）作只读语境**——不计入被审 sha、不入报告范围，防指代链/论证单元被切点切断而误判（R10）。**R11-B（2026-08-31）**：散文巨块已在 Step 1 强制再切，半块甜点区由 8-15KB chunk 天然保证；fence/表格原子巨块超限时半块仍可超限——罕见残余，v1 接受，v2 可按 R11-A 方案（~15KB 切 N 段）补。**对抗复审 A10 维持案 a（2026-08-31）**：表格数字另有 Step 5 ⑥ 硬判兜底（表内数字全部进"原文数字 ⊆ 译文"），残余限于单位/标签误译；M3 标定时观察真实巨表案例，再定是否提前 R11-A。
- **准确性**：fork evaluate-translation-prompt + 数字/否定词/条件句专项。
- **翻译腔**：fork evaluate-translationese-prompt，点名**逻辑连接词与指代衔接**子项（接缝与跨句高发区——R19）。
- **AI 味**：fork evaluate-ai-tone-prompt。
- **可读性**：全覆盖，**每 chunk 尾部 500 字定向关注**（长生成尾部质量洼地）；每 4 个 chunk（工作值，M3 校准）与范文锚点做一次**文风对漂抽查**（R19）。
- **分节报告结构**：四份 prompt 均加"按原文小节分节报告 + 每节独立结论"要求；审校输入含 **per-chunk glossary 投影**（同交接包③，治大 glossary 膨胀——干跑 C-8）+ brief（无 glossary 无法判术语对错）+ **文风基准卡全文 + 范文锚点节选（~1-2KB）**——判卷口径 = 对照文风卡判偏离，不按"通用好中文"修原文刻意文风（至少喂可读性与 AI 味两维——R7）。
- 不合并、不抽样；每份报告**头部记被审半块译文 sha**；undersize/模板签名检测，**阈值随送审单元大小缩放**。
- **异模型**：审校尽量与翻译异模型；环境不可控时**报告记录模型 id + REPORT 披露**（披露不验证——身份无法结构化核验，2026-08-30 评审口径）。

### Step 7 修复闭环 `[主+脚本]`
- 按报告修复译文 → 重跑 Step 5 → sha 变更自动标记相关报告 stale → 重审该维度。
- 每 chunk 重审 ≤3 轮；超限自动**升级**：换模型重翻该 chunk；仍不收敛 → **自动转 PENDING-USER 挂起**（2026-08-30 拍板：质量优先下不带病交付，消灭"待决清单死锁"）——不存在降级路径。**升级计数器规则冻结（G6，2026-08-31，原 §7.5 待定项收口）**：①升级后该 chunk 重试计数器清零；②每轮修复循环中升级至多发生一次；③**累计升级 ≥2 次（跨轮累计，不随清零重置）→ 直接转 PENDING-USER**——升级不是无限重试的入场券。
- **升级重翻附随**（2026-08-30 评审补充）：重翻 prompt 必附邻 chunk 实际中文首末段 + 文风基准卡；重翻后对该接缝做 scoped 统稿 + 可读性 seam 复查；下游（仅 N+1 邻 chunk 的 handoff②/串行增强段，见横切 re-keying 冻结语义——R1）stale 级联按 sha 机制处理。

### Step 8 合并与统稿 `[脚本+subagent×1]`
- merge **只由脚本执行**：manifest 顺序、只收"最新机械校验 passed"chunk；清临时标记（残留必须 0）→ **临时名**落盘（不命中 deliverable 模式）。
- 统稿 pass：fork consistency-checklist.js 全量扫描（术语/密度离群/标题译法/间距/接缝/**文风基准遵从**）→ 决策 subagent 只读清单下结论 → 机械应用 → 重跑受影响 chunk 的 Step 5。
- **译文变更分类 → stale 规则**（2026-08-30 评审冻结）：①**修复类**变更 = 相关维度报告 stale 重审（Step 7 既有规则）；②**统稿类**变更 = 仅限术语表驱动的机械替换，逐条 diff 清单落盘，consistency 清单重扫代替四维重审，REPORT 披露；句式级统稿改写仍走四维重审。**统稿轮 ≤2**，超限转 PENDING-USER——统稿↔修复循环有终止条件。

### Step 9 全稿通读与验收准备 `[subagent×1-2 + 主]`（终检之前——2026-08-30 三方评审一致裁决）
- **终稿冷读者 subagent ×1-2**：全稿通读（>30KB 分段接力：**段间重叠 ~2KB + 递进式发现台账 + 收尾专读全部接缝与各 chunk 首末段**——接缝恰是跨章不一致高发区），以读者身份对照**文风基准卡**找文风断裂、明显错误、跨章不一致。**>100KB 强制 ≥2 名冷读者独立通读、发现取并集**（R19）。
- **发现分流（冷读者有牙齿）**：错误类 → 走 Step 7 修复闭环；文风类 → 统稿式定点修 + 接缝复查 + 冷读者复核。**发现清零或复核通过**才放行下一步。**冷读定点修计入统稿轮 ≤2**（R3 裁决 2026-08-31，单套计数器），超限转 PENDING-USER；**双冷读者意见不合一 → 发现取并集**全部走上述分流、逐条标注来源与分歧，不加第三读者（预算纪律）。
- 主 agent PM 通读：**脚本化分层选样 ≥20%**（每 k 个 chunk 必抽 + 升级/接缝 chunk 必抽——选样由脚本定，防挑软柿子）+ 全稿标题级快扫；结论写 `pm-review-`（每次终检重入随重入重新生成，**头部记覆盖的 merged-draft sha 供 final-gate 校验——R15**）。pm-review 含**步骤合规表**：每步一行 ✅/异常记录；**质量维度（准确性/翻译腔/AI味/可读性/冷读）不存在 SKIPPED 合法标记**（FR-7 落点）。
- 关卡：冷读者发现清零（或复核通过）+ pm-review 落盘。

### Step 10 终检与交付（交付门） `[脚本]` ——**流程真正的最后一个动作**
- **重执行一切确定性检查**（不信任何落盘日志）：对最终产物重跑机械校验全项；从 translated-chunks 重导出 merged 做 diff；拼接 sha 复核；完备性矩阵（分母=原文钉死）；报告签名扫描（阈值随送审单元缩放）；**植入缺陷能力核验**。**括注对账双向相等（G3，2026-08-31）**：译文最终括注集合 === 裁定台账"保留"集合（空集对非空台账即 FAIL——堵"全删 «» 零工作量合规"）；**精选表兑现硬判**：special-phrases 精选表条目出现于该 chunk 原文者，必须以括注形态出现在译文（输入为落盘文件，机械可判；实现随 M1b 契约冻结）。**冷读/pm-review 结构化核验（G4，2026-08-31）**：冷读台账须逐段记覆盖（段号/起止 sha/发现数接力），终检机械核对覆盖矩阵 = 全稿（"无发现"自述不算数）；pm-review 选样清单由脚本落盘，终检核对样本集全覆盖且逐样本有实质结论。
- **探针注入机制**（2026-08-30 评审冻结）：探针作为**伪审校单元由 status 队列注入**——路径形态与真 chunk 无差别，主 agent 照单派发（不靠自觉混入，守零信任）；**每维度每 run（run = final-gate 一次完整执行——R20）≥1**；**探针单元缺报告 = 终检直接 FAIL**；ground truth（缺陷类型+预期命中点）由源侧 probe 脚本生成（manifest 不落工作区），终检比对报告是否实际命中。威胁模型边界：防偷懒型造假，不防能读源仓的对抗型伪造（签名/undersize 兜底）。
- **新鲜度**：产物集合与豁免清单**精确到 glob**（豁免 mtime 检查：pm-review、REPORT.md、progress.json/状态文件、verify-results.json、探针中间件（= `probes/` 目录）、终检报告自身；**pm-review 的 merged-draft sha 内容锚不豁免**——R15/R20）；固定顺序 = 冷读发现清零 → pm-review 最后写（记 sha 锚）→ **终检最后跑** → PASS 时脚本**原子改名**为正式交付名 → REPORT 定稿；mtime 只作 WARN，硬判锚 = 内容 sha + 重执行结果。
- 判定：**PASS** → 交付物正式落盘（SessionEnd/Stop hook 自然发布，零介入闭环）+ REPORT 定稿 + **交付摘要内联到聊天输出**（含交付物绝对路径；**回显原文 sha1 与 chunk 数供用户对照 Step 0 预算公告——分母外锚的对照端（G1）**；明示"本会话退出时将自动发布，请现在抽查，不满意可'重翻第 N 章'"——R17/R20）；**FAIL** → 自动定位打回，**故障半径分级（干跑 C-7 裁决）**：①根因限单 chunk（报告 stale/签名）= scoped 重做——该 chunk 回退 Step 6/7 + 接缝复查 + pm-review 重生成，其余成果与冷读台账保留；②全局性根因（拼接 sha/完备性/探针未命中）= 全局阶段整体作废重走。连续 FAIL ≥3 次转 PENDING-USER，不无限空转。**准确性维度缺失 = 无条件 FAIL**（不可降级）。URL 源终检可选重取比对原文（仅 WARN——重取失败不阻塞交付，披露即可）。
- `REPORT.md` 体检报告：**首屏一句人话结论**（如"可发布；第 3 章数字密度高，建议人工抽查 5 分钟"）+ 四维各一句 + 覆盖明细 + **章↔chunk 映射对账**（R5）+ **消耗对账（预估 vs 实际，含"用户开口次数/会话接力次数"）** + 异常与升级记录 + 遗留问题 + audit 使用说明；内部术语（探针/半块/stale 等）附人话括注，如"探针 4 次 = 故意埋 4 处错看审校能否全抓到"（R20）。
- audit 命令：用户可随时运行（指向源仓库只读脚本，M5 落地），输出人话 PASS/FAIL——可选项，不阻塞。

### 横切：状态机与续跑 `[脚本]`
- 一条状态命令 = resume oracle（冷启动入口；同文件再触发自动检测进行中并续跑）；**输出含用户视角人话一行**（当前 X/Y、阶段、已耗时、按 M3 基线的剩余预估、下次该说的话）——一物两用，同时就是干净退出提示。状态纯推导自文件系统。**输出双段契约**：人话一行（用户视角）+ **动作指令**（主 agent 视角：step / inputs[] / outputs[]）——探针在动作指令中与真单元不可区分，主 agent 照单派发（R13）。
- **原文变更 re-keying**：chunk **按内容 sha 匹配**（非序号）——未变内容的 chunk 即使换号也保留成果；原文 sha 变更 → **仅内容 sha 实际变更的 chunk 作废重翻**（未变更 chunk 一律保留成果，绝不因位置/序号重翻——"下游"冻结语义，R1），全局阶段（merge/统稿/冷读/终检）**整体作废重走**。**handoff 与 Step-2 产物失效规则（干跑 C-5 补）**：受影响 chunk 及其 **N+1 下游邻 chunk（仅此一个）** 的 handoff ②摘要与串行追加段失效重生成；map.md 对应条目更新；chunk 文件按新 manifest 重排命名（内容 sha 匹配保的是**成果**，文件名随新序号）；glossary/style-card/anchor 保留，仅当原文变更面积 >30% 时触发重新预检。
- **用户动词表**（全部挂 resume oracle，触发词写进 SKILL.md description）：`继续翻译 <title>`（续跑）、`翻译进度 / <title> 翻到哪了`（人话进度）、`停止翻译 <title>`（封存标记 + 一行总结，不再提示继续）、`重翻 <title> 第 N 章`（执行前一行披露章↔chunk 映射，如"第 3 章 = chunk 05-06"；作废范围按 re-keying 冻结语义：仅命中 chunk 重翻、N+1 handoff 重生成、全局阶段重走——R1/R5）。**小文档（≤40KB）自动交接** translator，不让用户重发。
- 会话预算：每会话处理 N 单元后干净退出；每单元幂等；N 同时约束内存与主会话上下文增长（默认值 M3 标定）；**单元 = 一次 subagent 调用**（与 §4 预算表 ~88/64KB 口径对齐——R14）。
- **subagent 回传纪律**：subagent 仅回传 落盘路径 + 一行结论 + FAIL 项计数；报告/产物全文只落盘、不回传主上下文——O(1) 主上下文的最后一道闸（R20）。
- **限流自动退避**：调用失败按指数退避自动重试；超限窗口转挂起 + 干净退出提示——不让限流夜变成用户的推杆夜。
- **并发参数 `--concurrency N`（默认 1；N>1 实现推迟 v2，2026-08-30 拍板——参数位保留，消灭 v1 全部并发共享状态问题）**：仅限"尴尬并行"阶段（翻译/裁定/机械校验/审校）；统稿、冷读者、终检永远单发；禁止自动上调。v2 实现时：subagent 只写本单元独占路径，共享状态仅主 agent 串行写，内存检查进 status 脚本。
- **上下文溢出防护**（2026-08-30 裁决）：主 agent 不依赖会话记忆——一切状态落盘、每单元完成即检查点；/compact、上下文压缩、溢出与 OOM//clear 同路径（重跑状态命令即恢复）。冷读全稿 >30KB 分段接力。
- **PENDING-USER 挂起态**（极简实现：`pending.md` 标记文件 + status 识别）：必须用户的节点（付费授权/内容违规裁量/**待决清单终态**）→ 挂起 + 干净退出附一行说明，处理后自动续跑——零介入唯一合法例外。pending.md 写明**选项菜单**：①继续（系统侧换模型/调参并记录新参数；FAIL 类挂起则 = 按半径分级重走 scoped/global）②用户手修译文文件后说"继续翻译 <title>"，该 chunk 按新 sha 自动重审（**手修路径机械后果见 Step 5 G7 条款：间距类违规脚本自动补空格后重跑、手修 chunk 永不自动重翻**——手修是解挂出口，不是新的打回源） ③终止项目；status 挂起态"下次该说的话"输出此菜单——防"回句继续→原路径重跑→再挂起"的推杆循环（R2，复审补 FAIL 适配与②闭环话术）。

### 5.1 工作目录文件命名 schema（M1b 接口冻结，2026-08-30）

> 依据 refined-stock `scripts/lib.mjs` classify() **真实代码**验证：任何位置以 `-zh.md` 结尾的文件都会被发布（translator 类目色）；`summary-` / `talk-` / `merge-` 前缀、`final-|recommendation-`+数字尾、根级裸 .md 亦命中发布；**嵌套的非模式 .md 不发布**。下表所有中间产物命名均已避开全部模式。

```
xl-translator/<title>/
├── original-<title>.md                          # Step 0 原文（markdown 化后）
├── brief.md                                     # 翻译偏好（缺省值落盘）
├── analysis-<title>.md  /  glossary-<title>.md  /  keep-list-<title>.json  /  special-phrases-<title>.md   # Step 2
├── style-card.md                                # 文风基准卡
├── chunks/chunk-<NN>-<slug>.md                  # Step 1；fence/表格原子巨块超限单 chunk 用 chunk-<NN>X-（X 标记超限，仅原子块可得——R11-B；散文巨块强制再切）
├── handoff/
│   ├── map.md                                   # 全文 chunk 地图（五件套①，含标题树既定译名——R19）
│   ├── chunk-<NN>.md                            # 该 chunk 交接包（②-⑤）
│   └── anchor.md                                # 范文锚点（chunk 1 过审后生成；文体分化的书按部分节存多锚点——R19）

├── adjudications/adjudication-chunk-<NN>.md     # 阶段B 裁定台账

└── translated-<title>-zh.md                     # ★ 唯一正式交付物：final-gate PASS 时原子改名产生
```

**命名规则**：
- `<title>` slug：字母/数字/连字符，≤6 词（继承 translator 规则）；`<NN>` **两位起、自然增长**（三位自然扩展，`padStart(2)` 已兼容——G9，2026-08-31；status/final-gate 一律按 NN **数值解析排序，禁字典序**，防 5MB 级 600+ chunk 时 `chunk-100` 错排）；`<dim>` 四个固定值；`<h>` ∈ a|b
- **全局/chunk 分辨规则（2026-08-31 Yiyue 要求）**：chunk 级文件名必含 `chunk-<NN>` 段（`chunk-`/`chunk-<NN>X-`/`translated-chunk-`/`review-<dim>-chunk-`/`handoff/chunk-`/`adjudication-chunk-`）；全局文档文件名禁含 `chunk-`（`original-`/`analysis-`/`glossary-`/`style-card`/`map`/`anchor`/`manifest`/`progress`/`merged-draft`/`REPORT` 等）——仅凭文件名（不看所在目录）即可判定作用域；status.mjs/final-gate.mjs 的 glob 与分类以此为准。`probe-<dim>-<k>` 为 run 级样本，不属 chunk 域
- **路径超长防护（2026-08-31 Yiyue 要求）**：Windows 260 上限不依赖系统长路径开关；segment 产物路径 >240 先缩 `<slug>`（唯一性由 `<NN>` 保证，缩名记入 manifest 操作日志），目录本身超限报错（退出码 4）并提示缩短 `--out`/`<title>`
- **发布安全红线**：PASS 前全目录**唯一**允许命中发布模式的文件名是最终交付物；任何中间文件禁止以 `-zh.md` 结尾或以 `summary-` / `talk-` / `merge-` / `final-` / `recommendation-` 开头
- 审校报告元信息记**文件内容头部**（非文件名）：`sha:`（被审半块译文 sha1）、`model:`（模型 id）、`time:`——终检按内容解析
- status.mjs / final-gate.mjs 按本表 glob 约定工作；新增文件类型必须先入本表再编码
- **半块切片规格（干跑 C-1 冻结，2026-08-30；G5 修订 2026-08-31）**：半块 = `translated-chunk-NN.md` 按**字节中点向最近段落边界取整**切两份（a=前段，b=后段）；半块 sha = 该字节区间的 sha1，**由 status/final-gate 从译文文件重算**（半块**不以最终形态落盘**——派发时经统一物化暂存，见 C-6，防输入形态差暴露探针）；Step 7"相关报告"量化 = **内容 sha 实际变化的半块 × 全部 4 维**（a 修复仅触发 a 的报告 stale，b 不级联）
- **探针落位（干跑 C-6 裁决；G5 统一物化 2026-08-31）**：探针**报告**落 `reviews/`（与真单元同路径形态）；`probes/` 只放样本输入，**且不出现在派发指令与新鲜度豁免 glob**——所有送审单元（真半块 + 探针）由 status 以**同构暂存命名/同通道物化后派发**，探针与真单元的差别只存在于源侧 ground truth，不存在于被审者可见的任何输入形态（防"识别探针→只对探针认真、真单元盖章"）；完备性矩阵分母不含探针（探针由 final-gate 单独核对命中）；**run = final-gate 一次完整执行，`<k>` = run 内序号，每维度每 run ≥1 由 final-gate 核对（R20）**
- **slug 规则（干跑 C-9）**：`<slug>` = chunk 首 heading 前 3-4 个词、连字符连接、≤30 字符；签名/undersize 阈值缩放公式 M1c 具体化（初值 base × unitKB/4）
