# 交付模板（Step 10 元信息 + 交付摘要 + REPORT 人工补充段）

> 分工：**机器部分**（首屏结论/覆盖矩阵/sha 锚/FAIL 清单）由 final-gate.mjs 定稿渲染进 REPORT.md；**本模板管人写部分**——交付摘要（聊天输出）与 REPORT 人工补充段。**追加语义**：人工补充段在 final-gate PASS 落盘 REPORT.md **之后**由主 agent 追加到文件尾部（终检重入时会被机器渲染整体覆盖重生成，属预期——判据只在机器段）。

## 一、交付摘要（聊天输出，PASS 后内联）

必须含（零介入闭环：用户不读文件也能验收）：

```
✅ 翻译完成：<中文标题>（<title>）

- 交付物：<绝对路径>（sha1 前 12：<锚>——内容锚，手改即不符）
- 原文 sha1（前 12）：<锚>｜chunk 数：<N>（对照开工公告——分母没变）
- 元信息：<见下方元信息块一行摘要>
- 本会话退出时将自动发布，请现在抽查；不满意可说"重翻 <title> 第 N 章"
```

## 二、元信息块

```markdown
> **原文**：<原始英文标题>
> **作者**：<author 或空>
> **来源**：<url 或空>
> **翻译日期**：<日期>
> **风格**：<意译 或 直译>（brief）
> **字数**：<交付物字数——word-counter 统计交付物自身>
```

用于交付摘要与 REPORT 补充段头部，并**作为交付物文件头的字段源**（final-gate PASS 改名时前置——字段以此块为准；块置于全文最前、`---` 分隔，**不另加 H1**：标题 H1 由 chunk 01 译文自带，块不得插在 H1 与其锚行之间）。作者/来源取 brief.md 可选行（Step 0 取文可得时落盘）。

## 三、REPORT 人工补充段（追加到 REPORT.md 尾部）

final-gate 机器段之后追加，各段必须实质（"一切正常"不算结论）：

```markdown
## 四维各一句（人工结论）

- 准确性：<如"数字密集章（03/07）复核通过，无范围漂移">
- 翻译腔：<如"连接词错位 2 处已修；指代衔接无悬空">
- AI 味：<如> ...
- 可读性：<如"尾部 500 字定向无退化；文风对漂 2 次抽查在轴内">
- 冷读：<如"接缝专读发现 3 条，全部清零">

## 章 ↔ chunk 映射对账

| 章 | chunk |
|---|---|
| 1 | 01-02 |
| 2 | 03-05 |

## 消耗对账（预估 vs 实际，无硬顶只披露）

- subagent 调用：预估 ~<N> / 实际 <M>（升级 <k> 次、探针 <p> 次）
- 用户开口次数：<n>；会话接力次数：<m>；返工轮次分布：<...>

## 异常与升级记录

- <每次升级/挂起/重入：chunk、原因、动作、结果；无则"无">

## 遗留问题

- <交付后建议人工抽查点（如"第 3 章数字密度高，建议抽查 5 分钟"）；无则"无">

## audit 使用说明

随时可说"审计翻译 <title>"/"查翻译质量"（audit 入口，M5 落地前以本报告为准）。
```

**人话括注**：内部术语首次出现处附人话，如"探针 4 次 = 故意埋 4 处错看审校能否全抓到"、"半块 = 每块译文切两半分两次送审"、"stale = 译文改过、旧报告自动作废"。
