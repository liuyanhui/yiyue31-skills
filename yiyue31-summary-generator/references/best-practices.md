# Summarization Best Practices

## Core Principles

### Fidelity First
- Never add information not present in the original article
- Preserve the author's terminology and technical language
- Represent controversial positions accurately, attributing them to the author
- Distinguish between claims and evidence

### Structural Clarity
- Follow the standard template: Overview → Key Points → Technical Details → Takeaways → Conclusion
- Use parallel structure in bullet points (e.g., all start with verbs)
- Group related points together rather than listing randomly
- Use formatting (bold, code) to highlight key terms

## Content Selection

### What to Include
✅ Main thesis or argument
✅ Supporting evidence and data
✅ Technical concepts and terminology
✅ Code examples or pseudocode (if brief and critical)
✅ Author's conclusions and recommendations
✅ Context about why the topic matters

### What to Exclude
❌ Repetitive points (keep the strongest instance)
❌ Tangential anecdotes or examples
❌ Standard background (assume tech audience knows basics)
❌ Minor details that don't affect understanding
❌ Author's bio or promotional content

## Section-Specific Guidelines

### Overview
- **Length**: 2-3 sentences
- **Content**: What + why + how (high level)
- **Tone**: Objective and factual
- **Avoid**: Details, examples, technical specifics

### Key Points
- **Length**: 3-7 bullets
- **Format**: Full thoughts, not fragments
- **Order**: Most important first
- **Each point**: One main idea, specific and concrete

### Technical Details
- **Length**: 1-3 paragraphs
- **Depth**: Match the article's technical level
- **Content**: How it works, specific technologies, architecture
- **Audience**: Technical readers who need substance

### Takeaways
- **Length**: 2-4 bullets
- **Focus**: Actionable or conceptual
- **Format**: Practical applications, lessons learned
- **Value**: What the reader can do with this knowledge

### Conclusion
- **Length**: 1-2 sentences
- **Content**: Who should read this, why it matters
- **Tone**: Evaluative but objective

## Common Patterns

### Tutorial/How-to Article
- Emphasize the learning outcome
- Note prerequisites mentioned
- Highlight key steps or gotchas
- Include practical takeaways

### Opinion/Thought Leadership
- Identify the core argument
- Note supporting evidence
- Capture nuance and qualifiers
- Attribute opinions clearly

### Technical Deep Dive
- Preserve technical accuracy
- Explain unfamiliar concepts briefly
- Include relevant code/config snippets
- Note performance implications

### Research/Academic
- State research question clearly
- Summarize methodology at high level
- Highlight key findings
- Note limitations or caveats

## Quality Checklist

Before finalizing a summary:

- [ ] Overview captures the article's main purpose
- [ ] All major points from the article are represented
- [ ] Technical terminology is used correctly
- [ ] No information is fabricated or misinterpreted
- [ ] Structure follows the standard template
- [ ] Bullet points are parallel and scannable
- [ ] Length is appropriate (not too brief, not verbose)
- [ ] Tone matches the article's intent
