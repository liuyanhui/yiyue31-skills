# 用户心得分享 Skill

读到好文章（技术/新闻）后，快速产出**可分享的中文心得成品**。AI 不盘问、不替用户下判断，只呈现原文内容、整理用户的话；任何加值一律经用户确认（提案制）。

## 功能特点

- **提案制护栏 + 忠实护栏**：AI 的所有加值（角度、结构、强化、读者 / 编辑建议）都是提案，逐条由用户确认才入稿；dump 模式另加 faithfulness 检查防 AI 发挥。
- **两条路径 × 两种形态**：dump（分批写、AI 整合）/ 策展（AI 摆点、你挑你批注）；形态分享走自由结构、归档走模板，路由时选一，另一种按需再出。
- **加法门 + 减法门**：组装后先跑"读者 / 编辑提议轮"（加法，建议供确认），再跑翻译味儿 / 可读性 / AI 味儿三道减法检查。
- **断点恢复**：每步交互落盘 `progress-{title}.json`（路由 / 形态 / 当前步骤 / 决策台账，单一权威来源）+ `journal-{title}.md`（逐次交互日志）；中断后说"继续心得 / 恢复 talk"即可精确续做。会话写在**工作目录**（跟着项目走），整个 `{title}/` 文件夹随项目搬到另一台设备（git / 网盘 / 拷贝）即可跨设备续做。
- **参考资料（任意追加）**：会话可随时补充参考资料（URL / md / txt），URL 内容抓取后随会话存到 `refs/`（含溯源清单），与原文、用户看法同属合法来源，跨设备随项目流转。

## 路径与形态

| | 适用 | 流程 |
|------|------|------|
| **dump** | 心得已成形 | 你分批写所有看法 → AI 忠实整合（不编造）→ faithfulness 检查 → 组装 |
| **策展** | 心得未成形 | AI 提原文点(≤5) → 你多选 + 打权重 → 选择性加批注 → 组装 |

形态（独立于路径）：**自由结构**（分享，钩子前置）/ **模板**（归档，固定四块）。路由时二选一，另一种按需再出。

## 工作流程

1. Step 0 输入格式化。
2. 路由：选内容路径（dump / 策展）+ 输出形态（自由 / 模板）。
3. dump：D1 分批写 → D2 AI 忠实整合 → D3 缺口提示(可选) → D4 faithfulness 检查。
   策展：C1 AI 提点(≤5) → C2 多选 + 权重 → C3 加批注（均可分批，说"done"才继续）。
4. 共用组装分享稿（按形态：自由结构先确认结构；模板按四块）。
5. 读者 / 编辑提议轮（加法，出建议供用户多选采纳）。
6. 质量审查（翻译味儿 + 可读性 + AI 味儿，并行，最多 2 轮）。
7. （可选）按需产出另一形态（re-skin + 无新增内容自查）。

## 输出文件

每次任务在 `{title}/talk/` 下生成的文件、路径与检查方式，见 `SKILL.md` 的「恢复逻辑」表（断点两件套见「断点与恢复」）——该处为唯一权威，避免两份清单漂移。

## 输出格式

固定中文。形态两种：**自由结构**（AI 提议结构 → 用户确认 → 钩子开篇、长短自由）/ **模板**（引言钩子先行 / 正文单一论点 / 总结 / 推荐语 ≤100 社交 + ≤200 博客）。全文区分原文 / 参考[X] / 我的话；数据 / 名称保持原值。

## 使用方法

触发短语："提取观点"、"生成心得"、"记录我的理解"、"写收获"、"我的想法"、"我对这篇文章的看法"、"分享我的看法"、"写个推荐"；中断后续做："继续心得"、"恢复 talk"、"接着上次"、"resume talk"。
